# agent-peers for Codex (CLI and desktop)

The Codex plugin `peers`. The Codex CLI and the Codex desktop app (ChatGPT.app) load the same tree; the
bridge tells them apart at runtime (MCP `clientInfo`, environment), so `--surface codex` covers both.

| Path | What it does |
|---|---|
| `.codex-plugin/plugin.json` | Manifest. Hooks are declared **inline** (`"hooks": { "hooks": { … } }`), the form OpenAI's bundled plugins ship. |
| `mcp.json` | Registers the stdio MCP server `peers` → `./bin/agent-peers mcp --surface codex`. Codex requires a bare command or a contained `./` path, so the absolute binary path lives in the shim. |
| `bin/agent-peers` | POSIX shim that `exec`s `${AGENT_PEERS_BIN:-${AGENT_PEERS_HOME:-$HOME/.agent-peers}/bin/current}`. |
| `skills/<cmd>/SKILL.md` | One skill per command, generated by `bun adapters/build.ts`. |
| `skills/<cmd>/agents/openai.yaml` | `allow_implicit_invocation: false` for join, room, leave, invite, knock and dashboard. |

## Using it

Codex has no plugin slash commands. Use the skill mention or plain language:

```text
$peers:ask @work what's the retry policy in the payments client?
$peers:who
```

In the desktop app, type `@peers` (or `$`) and pick the skill.

## Hooks

Every hook is an `mcp_tool` handler that calls the bridge's hidden `peers_hook` tool on the already-connected
`peers` server. No shell script and no control socket are involved.

| Event | Input (templated from the hook event) | Bridge behaviour |
|---|---|---|
| `SessionStart` | `session_id`, `source`, `cwd`, `model` | Register the thread (it may run before the server is ready; then registration happens implicitly on the next hook). |
| `UserPromptSubmit` | `session_id`, `turn_id`, … | Activity `busy`; hand pending envelopes over as `additionalContext`. |
| `Stop` | `session_id`, `turn_id`, `stop_hook_active`, `last_assistant_message` | `turn_end`; reply nudge once via `{"decision":"block","reason":…}`; deliver held envelopes. |
| `PreToolUse` | `session_id`, `turn_id`, `tool_name`, `tool_use_id`, `tool_input` | Peer-turn tool gate: `permissionDecision: "deny"` for tools off the allowlist. |

`turn_id` is a Codex extension on turn-scoped events only, so `SessionStart` does not template it. Every
`tools/call` also carries `_meta["x-codex-turn-metadata"].thread_id`, which the bridge uses to identify the
calling thread without a `session_key` argument.

**Hooks need trust.** Installing a plugin does not trust its hooks. After installing (and after every
upgrade, because trust is per hook hash): CLI → open `/hooks` and trust `peers`; desktop → **Review hooks**.

## Approving `peers_reply` without a prompt

A peer turn can run while you are away, so the reply tools must not stall on an approval prompt. Add this
to `~/.codex/config.toml` (the installer does it for you, and `remove` takes it out again):

```toml
[plugins."peers@agent-peers".mcp_servers.peers.tools.peers_reply]
approval_mode = "approve"

[plugins."peers@agent-peers".mcp_servers.peers.tools.peers_progress]
approval_mode = "approve"
```

`approve` never prompts, whatever the tool's annotations say. Do **not** do this for `peers_join`,
`peers_create` or `peers_invite`: those always need your explicit OK (ARCHITECTURE §8).

## Install

```sh
codex plugin marketplace add <owner>/agent-peers --json
codex plugin add peers@agent-peers --json
```

For Codex desktop, use the bundled engine
`/Applications/ChatGPT.app/Contents/Resources/codex-cli/bin/codex` for the same two commands, then open a new
chat and review the hooks.
